LLMCost — plán subsite v1

Druhý wizard: kalkulátor nákladů LLM API na wizardcost.com/llm/. Dokument je zároveň ukázkou navržené palety — vše fialovo-magentové na téhle stránce je navržený akcent subsite v akci.

Analogie zelené automation — jeden akcent, tmavý umbrella základ beze změny.

02Wizard UX — 3 kroky

Automation má 4 kroky (role → workflows → volume → results). LLM use case je jednodušší — 3 kroky, stejná sliderová filozofie: engine odhaduje, uživatel přepisuje.

Krok 1
Use case

5 karet (vzor role-cards): Chatbot · RAG / search · Summarization · Agents · Data extraction. Single-select — use case řídí token odhady. Každá karta nese jednořádkový popis + mono meta („typicky dlouhý input, krátký output").

Krok 2
Volume & tokens

Slider requestů/měsíc (log škála, mono hodnoty). Pod ním auto-odhadnuté input/output tokeny na request s auto-estimated badge — přepsatelné. Chatbot navíc: „% of input served from cache" (auto-odhad, přepsatelný). Toggle „I can run batch / async" (sleva jen u potvrzených providerů).

Krok 3
Results

Měsíční náklad per model, seskupený podle tieru. Per-tier ranking, vítěz tieru zvýrazněn. Savings banner, Copy share link, resume banner — vzory z automation beze změny.

Krok 2 — detaily

  • Requests/měsíc: log slider 1k → 10M, kotvy 10k/100k/1M jako chips (vzor vol-chips z automation dema).
  • Tokeny na request: dva mono inputy (input/output) s auto-badge. Odhad per use case dodá engine; UI ukazuje přepočet „≈ {X} words" pro netechnické uživatele.
  • Cache slider: jen když je relevantní (chatbot, agents) — jinak schovaný v „Advanced". Cached input ~10× levnější je velká páka; banner ve výsledcích to umí vysvětlit jednou větou.
  • Batch toggle: popisek „Batch discounts where available (−50 % Anthropic, Mistral)" — seznam potvrzených providerů je datové pole, ne hardcode.

Krok 3 — výsledky a vizualizace ceny

Lineární bary přes 5 řádů nefungují ($0.14–$30/M input) — návrh: bary normalizované uvnitř tieru na odmocninové škále (sqrt — log by rozdíly opticky zploštil), vždy s mono číslem vedle. Mezi tiery se nesrovnává barem, jen čísly. Ilustrace (frontier tier, ilustrativní hodnoty — finální čísla z enginu):

  • Řádek modelu: jméno + provider logo-text, bar, měsíční cena mono. Rozbalení řádku → breakdown input/output/cached/batch.
  • Tier = sekce s mono labelem (FRONTIER / MID / BUDGET) + tooltip „our editorial grouping — model classes change, we re-sort on every pricing revision". Tier vítěz nese --accent-br.
  • Capability chips u modelu, jen kde rozhodují: „1M context" (Grok, DeepSeek), „batch −50%". Žádné benchmark skóre — nejsme leaderboard, jsme ceník.
  • Savings banner: „{Model A} saves you ~${X}/yr vs {Model B} in the same tier" — srovnávat jen uvnitř tieru (cross-tier srovnání je ten nesmysl, který grouping řeší).

Landing /llm/ — wizard rovnou, ne hero-marketing

Doporučuji jiný model než automation (tam landing a kalkulátor jsou dvě stránky): LLM publikum jsou buildeři — chtějí číslo, ne pitch. Landing = krátký hero (H1 + jedna věta + trust řádek „prices verified {month}") a hned pod ním krok 1 wizardu inline. Žádná samostatná calculator.html.

  • Demo čísla v hero: jeden řádek à la automation homepage demo — „Chatbot, 100k requests/mo: from $14/mo (DeepSeek V4 Flash) to $3,000/mo (Fable 5)" — rozsah je sám o sobě argument. Hodnoty z enginu, ne z ruky.
  • vs-stránky v v1 nejsou — u modelů se páry mění s každou generací modelů; počkat na GSC vzorec z automation.
  • Email capture: reuse blok z automation — otázka 5 níže (jeden seznam vs. druhý).

05Otevřené otázky (blokují mockupy)

  1. Cache odhady: dává engine default „% cached input" per use case (chatbot ~70 %?), nebo mám navrhnout vlastní defaulty ke schválení?
  2. Batch: potvrzený seznam providerů se slevou — UI ho bere jako datové pole; stačí mi vědět, že do launche bude v datech.
  3. Přesnost odhadu: ukazuje engine u výsledku rozptyl („$212–340/mo" při nejistém token odhadu), nebo jedno číslo? Ovlivňuje layout řádku.
  4. Per-provider stránky v1: všech 6, nebo launch s top 3 (OpenAI, Anthropic, Google) a zbytek dogenerovat? Šablona je stejná, jde o obsah poznámek.
  5. Email capture: price-drop alerts pro LLM = nový MailerLite seznam/skupina, nebo společný s automation? Disclosure „price-change alerts only" funguje pro oba, ale subscriber z automation nečeká LLM maily — doporučuji oddělit.
  6. Slug konvence: google-pricing.html vs gemini-pricing.html (search volume vs. konzistence „provider, ne produkt") — rozhodni podle GSC zkušenosti.
